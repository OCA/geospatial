# base_geoengine_demo: 17.0 -> 18.0 migration log

## Changes

- Manifest version bumped `17.0.1.0.1` -> `18.0.1.0.0`.
- `README.rst` / `static/description/index.html` regenerated by the OCA
  `oca-gen-addon-readme` pre-commit hook (branch references updated 17.0 -> 18.0).
- XML views (`views/zip.xml`, `views/retail_machine.xml`): `<tree>` -> `<list>` tag
  rename and `view_mode="tree,..."` -> `view_mode="list,..."`, applied automatically via
  Odoo's native `upgrade_code` tool (`odoo/upgrade_code/17.5-01-tree-to-list.py`, part
  of the 17.0 -> 18.0 core rename of the tree/list view type). No `attrs`/`states` usage
  was found in this module, so no attribute-syntax migration was needed.
- No Python API breakage found: `models/geo_npa.py` and `models/retail_machine.py`
  needed no changes.

## Dependency

`base_geoengine` (this module's only dependency) was already fully migrated to 18.0
(`18.0.1.2.1`) prior to this work.

## Testing

- Clean install verified on a fresh 18.0 database (`base_geoengine_demo` +
  `base_geoengine` both installed successfully, no errors/tracebacks).
- Demo data loads correctly: 455 `dummy.zip` records, 37
  `geoengine.demo.automatic.retailing.machine` records.
- `odev test -i base_geoengine_demo` was attempted but is not meaningful here: this
  module ships no tests of its own, and the command re-installs+tests the full
  dependency graph including Odoo core `base`/`web`, which surfaced failures unrelated
  to this migration (missing `rlPyCairo` render backend for a `base` QWeb barcode test,
  headless-browser HOOT JS test failures, and log-level-dependent `base` test
  assertions). None of these touch `base_geoengine`, `base_geoengine_demo`, or any
  geospatial code.
- `ruff check --select F821,F822,F405` and `xmllint --noout` pass on all files.
